# PostHog Connector — Preparation

**Category:** C40. Product Analytics & Behavioral  
**Status:** App Preparation Complete (Genuinely Vendor-Specific)  
**Standard:** APP_PREPARATION_STANDARD.md

## 1. Паспорт коннектора
- **Название:** PostHog Connector (`posthog-connector`)
- **Официальный портал вендора:** https://posthog.com
- **Базовый API:** `https://app.posthog.com/api`
- **Модель аутентификации:** Personal API Key (Authorization: Bearer <key>)
- **Назначение:** Интеграция платформы Imperal Cloud с PostHog для автоматизации предметной области: open-source продуктовая аналитика полного цикла: запись сессий, когорты, фиче-флаги и воронки в одном окне.

## 2. Решаемая проблема
Когда **Full-stack разработчик** сталкивается с задачей **open-source продуктовая аналитика полного цикла: запись сессий, когорты, фиче-флаги и воронки в одном окне**, возникает необходимость ручного мониторинга, дублирования статусов и переключения между окнами. Это приводит к потере времени, замедлению реакции на инциденты и ошибкам ручного ввода.

## 3. Роли и права доступа
- **Full-stack разработчик, продуктовый архитектор, аналитик**
- Принцип наименьших привилегий (Least Privilege): токен запрашивает доступ только к разрешенным операциям чтения и подтвержденным действиям.

## 4. Ключевые сущности
проекты (/projects), события (/events), когорты (/cohorts), инсайты (/insights), записи сессий (/session_recordings)

## 5. Первичный рабочий сценарий
`получение инсайтов дашборда -> сопоставление с когортами пользователей -> валидация фиче-флагов`.

## 6. Границы коннектора
- Изолированное хранение секретов (BYOC).
- Никаких фиктивных методов сторонних предметных областей.
- Деструктивные операции требуют явного подтверждения пользователя.
